<objective>
Build the shared state layer that every Phase 3 and Phase 3.1 screen reads and writes through: the single-writer `GymStateCubit` (D-04), the model helpers the feature Blocs need to edit openGym's JSON shapes without losing unknown keys, and the app wiring (load-before-runApp, flush on pause, per-feature provider files).

Purpose: openGym funnels every change through one `update(mut)`. Several Flutter Blocs writing `GymStateRepository` on their own would race on the single flat document. This plan makes one writer, so later plans only add events.
Output: `GymStateCubit`, `model_extras.dart`, `copyWith` on the nested models, a typed weekly plan accessor, ShellBloc moved onto the cubit, and three provider-list files that later plans fill in.
</objective>

    - `static Future<GymStateCubit> load({required GymStateRepository repository, String uid = kLocalGuestUid})`: awaits `loadState`; null gives `GymState.defaults()`. If loadState throws, start from defaults with `canPersist == false` (never overwrite an unreadable profile, T-1-12) and report through `addError` once the cubit exists.
    - `Future<void> mutate(GymState Function(GymState current) fn)`: mirrors `useStore.update`. Computes `next = fn(state)`, stamps `_ts` with `next.copyWith(ts: DateTime.now().millisecondsSinceEpoch)` (mirrors persist's `S._ts = Date.now()`), emits right away (the UI never waits on disk), then queues persistence. The returned Future completes when that write has finished.
    - `Future<void> replaceState(GymState next)`: mirrors `replaceState`. Same stamp, emit and persist path.
    - `Future<void> flush()`: awaits the in-flight write and any queued one.
    - `bool get canPersist`.
    Persistence queue: at most one `saveState` in flight. Changes made during a write are coalesced, so the next write carries only the newest state (the same intent as openGym's 800 ms nativePersist debounce, without a timer). A failed save calls `addError` and keeps the in-memory state; the next mutate retries with the newest state. Keep a `sync` push flag out of the API: server push is Phase 6 (SYNC-01) and appears in the UI-07 checklist as deferred.
