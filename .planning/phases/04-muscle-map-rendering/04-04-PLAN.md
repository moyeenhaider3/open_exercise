<objective>
Build the shared native body map: a lazy, process-wide geometry cache that parses the 04-03 SVG assets with `xml` and converts every `d` with `path_drawing`'s `parseSvgPathData` (MAP-01); a `CustomPainter` that shades muscles from bridged levels with openGym's exact colour ramps (MAP-02); tap hit-testing for the explorer and Stats (MAP-03 plumbing); and the three legends.

Purpose: one widget, `BodyMap`, replaces openGym's `components/BodyMap.jsx` at every call site (Stats x3, Muscle Explorer, RoutineEdit, FinishSummary). Levels are always computed by the caller through the JS bridge (`MusclesJs.levelsOf` / `MuscleViewJs`). The widget only maps level ints to colours, the same way `Heatmap` does.
Output: AppPalette.label; lib/core/body_map/{body_geometry_cache,body_map_painter,body_map}.dart.
</objective>

         - `base(p)` = `Color.lerp(p.surface, p.label, 0.11)`; `silhouette(p)` = `Color.lerp(p.surface, p.label, 0.18)`.
         - `muscle(BodyMapVariant v, int level, AppPalette p)`: balance l1/l2/l3 = lerp(base, acc, .32/.56/.78) and l4 = acc. Fatigue l1 = lerp(base, yellow, .32), l2 = yellow, l3 = orange, l4 = red. Strength is the same as balance except l4 = yellow. l0 and out-of-range levels = base.

       - `final class BodyMapFit`, computed from `(Rect viewBox, Size size)`: `scale = min(size.width / vb.width, size.height / vb.height)` and xMidYMid-meet offsets `dx = (size.width - vb.width * scale) / 2`, `dy = (size.height - vb.height * scale) / 2`. Provide `void apply(Canvas c)` (translate(dx, dy), scale(scale), translate(-vb.left, -vb.top)) and `Offset toViewBox(Offset local)` (the exact inverse). Paint and hit-test share this one class, so they can never disagree. dart:math `min` is allowed here: lib/core/body_map is presentation code, not an audited domain directory, and this is layout geometry, not domain math.
       - `class BodyMapPainter extends CustomPainter` with constructor `({required BodyViewGeometry view, required Map<String, int> levels, required AppPalette palette, required BodyMapVariant variant, String? selected})`. `paint` works in document order, per SVG semantics. For each part: fill with silhouette (inert) or `BodyMapColors.muscle(variant, levels[slug] ?? 0, palette)` (muscle). For strength with level 4, first draw the path in yellow with `MaskFilter.blur(BlurStyle.normal, 0.75 / fit.scale)`, so the glow is about 1.5 logical px on screen like the CSS drop-shadow. Then stroke the same path with `StrokeJoin.round`: `palette.label` at width 7 if the part is a muscle whose slug == selected, otherwise `palette.surface` at width 2.5. Widths are in viewBox units, applied after the canvas transform, so they scale with the map as SVG strokes do (research anti-pattern note).
       - `static String? hitTestMuscle(BodyViewGeometry view, Size size, Offset local)`: convert via BodyMapFit.toViewBox, iterate `view.muscles` in reverse (last painted = topmost, research Pitfall 6), and return the first part whose `path.contains(point)` is true. Inert parts are never returned.
       - `shouldRepaint` compares view, levels (mapEquals), palette, variant and selected.
