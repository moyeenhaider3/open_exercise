Design decisions for this plan (planner discretion, per Research "Recommended sqflite Schema" with fixes):
- Array order is significant (workouts are chronological) and legacy data may repeat or omit ids, so array tables key on (uid, pos) not (uid, id).
- bodyweight is one entry per day in openGym (sheets.jsx:210 find-by-d then overwrite), but a real file may still contain duplicates; (uid, pos) keeps them.
- The repository stores the raw decoded maps (no DEF overlay) so importState -> exportState returns the input exactly. The DEF overlay only happens when a GymState is built (loadState).
- Local import/export never strips `active` or stamps `_rev` (Research Pitfall 5: that is Phase 6 sync behaviour).
