Facade conventions (apply in every module file):
- File lib/core/js/modules/<module>_js.dart holds `final class <Module>Js { const <Module>Js(this._engine); final JsEngineService _engine; ... }` plus `extension <Module>JsAccess on JsEngineService { <Module>Js get <namespace> => <Module>Js(this); }`, so callers write `engine.onerm.estimate1RM(100, 5)`.
- Dart method name = JS export name (for example `estimate1RM`, `is1RMRecord`). Each method calls `_engine.call('<ns>.<fn>', <args>)` with a string-literal path, so coverage can be grepped.
- Inputs: use the Phase 1 models (GymState, Workout, WorkoutEntry, SetEntry, DropEntry, ClusterEntry) and pass `.toJson()`; primitives as num/String/bool. `exOrId` parameters are typed `Object` and accept only a String id or a Map<String, Object?> exercise (ArgumentError otherwise).
- Optional JS parameters with defaults become named optional Dart params. Pass `param ?? jsUndefined` so the JS default applies.
- Results: decode only through the js_codec helpers. Object results become JsonReader-based Equatable models (known fields + `extra`, `fromJson`/`toJson`, implements JsonEncodable), placed in lib/core/js/models/. Sets come back as SetEntry.fromJson, and so on.
- Dispatch file tool/parity/dispatch/<module>_dispatch.dart: `Map<String, ParityCall> <namespace>Dispatch(JsEngineService engine)` with one entry per inventory function, keyed exactly '<ns>.<fn>'. Each entry rebuilds typed inputs from the raw args (for example WorkoutEntry.fromJson(jsonMapArg(args, 0))), supplies an optional named param only when hasArg(args, i), and returns toPlainJson(result).
- SPDX header on every file. No arithmetic on JS results beyond type decoding (JS-04).
