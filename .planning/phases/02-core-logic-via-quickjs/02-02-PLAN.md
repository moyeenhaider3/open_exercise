<interfaces>
Pre-read by the planner from the published flutter_js 0.8.7 archive (pub.dev). The executor MUST re-confirm these against ~/.pub-cache/hosted/pub.dev/flutter_js-0.8.7/lib/ after `flutter pub get`:
- lib/flutter_js.dart: `JavascriptRuntime getJavascriptRuntime({bool forceJavascriptCoreOnAndroid = false, bool xhr = true, Map<String, dynamic>? extraArgs = const {}})`. Android -> QuickJsRuntime2(stackSize: extraArgs['stackSize'] ?? 1024*1024). iOS/macOS -> JavascriptCoreRuntime. `xhr: true` calls enableFetch() (network-capable fetch shim), so the bridge should pass `xhr: false`.
- lib/js_eval_result.dart: `class JsEvalResult { final String stringResult; final dynamic rawResult; final bool isPromise; final bool isError; }`. There is NO `stacktrace` field; the research code sample's `.stacktrace` is wrong.
- lib/javascript_runtime.dart: abstract `JsEvalResult evaluate(String code, {String? sourceUrl})`, `Future<JsEvalResult> evaluateAsync(...)`, `void dispose()`, `String jsonStringify(JsEvalResult)`, plus console/setTimeout shims installed in init().
- QuickJsRuntime2.evaluate: an exception gives isError=true with stringResult = exception.toString(). JavascriptCoreRuntime: isError = `result.startsWith('ERROR:')`. That is a string-prefix heuristic, so a legitimately returned string that starts with "ERROR:" would be misread as an error.
- flutter_js imports package:flutter in lib/flutter_js.dart, lib/javascript_runtime.dart and lib/extensions/fetch.dart, so a plain `dart run` (no dart:ui) is expected NOT to compile.
- iOS: ships only ios/flutter_js.podspec (no Package.swift), so the iOS build needs CocoaPods. The planner saw `which pod` fail on this machine ("pod not found"); `brew` exists at /opt/homebrew/bin/brew.
- Android: minSdkVersion 21, compileSdk 34, builds a native QuickJS lib via NDK.
</interfaces>
