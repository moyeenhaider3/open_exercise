Facade conventions (same as 02-05/02-06; restated because this plan runs in parallel with them):
- lib/core/js/modules/<module>_js.dart holds `final class <Module>Js { const <Module>Js(this._engine); final JsEngineService _engine; }` plus `extension <Module>JsAccess on JsEngineService { <Module>Js get <namespace> => <Module>Js(this); }`.
- Method name = JS export name; each calls `_engine.call('<ns>.<fn>', [...])` with a literal path. Inputs are Phase 1 models via toJson() (a `cfg` is a RoutineExercise; `rows`/`sets` are List<SetEntry>; `w` is a Workout; an `entry` is a WorkoutEntry; `S`/`st` is a GymState; `r` is a Routine) or primitives. Optional/defaulted params become named optional Dart params sent as `param ?? jsUndefined`.
- Object results become JsonReader-based Equatable models implementing JsonEncodable in lib/core/js/models/. Sets decode as SetEntry, entries as WorkoutEntry, routines as Routine.
- tool/parity/dispatch/<module>_dispatch.dart: `Map<String, ParityCall> <namespace>Dispatch(JsEngineService engine)`, one entry per inventory function keyed '<ns>.<fn>'.
- SPDX header everywhere. No arithmetic on JS results (JS-04).
