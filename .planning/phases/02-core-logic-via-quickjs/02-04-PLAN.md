<objective>
Build the JS-03 oracle: a plain-Node generator that runs the vendored openGym modules on curated scenarios taken from openGym's vitest files. It writes frozen JSON fixtures, cross-checks them against the literal vitest expectations, and embeds them in a Dart file for the device-run parity harness (02-08).

Purpose: "matches the vitest results exactly" needs a frozen, reproducible oracle. Several vitest inputs are derived at runtime from the EXDB catalogue (research Pitfall 3), so fixtures must be computed by executing the code, not scraped.
Output: the bridge inventory, the generator plus per-module case tables, a wrapper script, 7 fixture JSON files, and tool/parity/parity_fixtures_data.dart.
</objective>

<interfaces>
Fixture file schema (contract consumed by 02-08's harness). One file per module group:
{
  "schema": 1,
  "module": "onerm" | "bar" | "workout-model" | "progression" | "recovery" | "history" | "session",
  "openGymVersion": "<third_party/opengym/lib/VERSION>",
  "sourceSha256": "<sha256 of third_party/opengym/lib/MANIFEST.sha256; equals bundle __openGymLibMeta.sourceSha256>",
  "generatedBy": "tool/gen_js_fixtures.sh",
  "cases": [
    { "id": "<module>-NNN", "fn": "<namespace>.<export>", "args": [ ...JSON... ],
      "expected": <JSON> | {"$throws": true},
      "from": "<file>.test.js > <describe> > <it title>",
      "vitest": <optional JSON literal copied from the assertion> }
  ]
}
- `fn` namespaces are the entry.js names: onerm, progression, bar, workoutModel, recovery, history, sessionStart, sessionMerge.
- An omitted optional argument in a middle position is encoded as {"$undefined": true} (JSON has no undefined). Trailing omitted optionals are simply left out, so the args array is shorter. The harness maps the marker to "named parameter not supplied", which the facade sends as jsUndefined.
- expected = JSON.parse(JSON.stringify({ok: r === undefined ? null : r})).ok, where r = fn(...decodedArgs) and decodedArgs = JSON.parse(JSON.stringify(args)) with the markers turned back into undefined. This is exactly the bridge envelope from 02-03.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ../openGym test files -> case tables | Scenarios are read by a human/agent and curated; nothing is executed from the test files |
| Node execution of vendored code -> committed fixtures | The oracle output becomes the reference the shipped bridge is judged against |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Tampering | fixture expected values | mitigate | Expected values are only ever computed by executing vendored code. vitest literals are cross-checked with assert.deepStrictEqual and the run aborts on mismatch. Hand edits are forbidden, and regenerating plus `git diff` exposes any drift |
| T-02-14 | Tampering | stale fixtures vs bundle | mitigate | Fixtures record sourceSha256 = sha256(MANIFEST.sha256), identical to the bundle's __openGymLibMeta.sourceSha256. 02-08's harness FAILs on mismatch |
| T-02-15 | Repudiation | non-deterministic oracle | mitigate | The three-timezone diff -r gate in tool/gen_js_fixtures.sh; the wall-clock-dependent history.streakWeeks is banned from fixtures |
| T-02-16 | Information disclosure | fixture data | accept | Fixtures are synthetic scenarios from openGym's public test suite; no user data. They ship only in a tool/ Dart file that is never imported by lib/ |
| T-02-SC | Tampering | npm packages | accept | The generator uses Node built-ins only (no new packages) |
</threat_model>
