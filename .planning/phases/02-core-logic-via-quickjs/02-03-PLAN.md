<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dart data (user-entered notes, exercise names, synced server JSON) -> JS source string | Untrusted strings are placed into code that the engine evaluates |
| App asset -> JS engine | The bundle asset is eval'd with full engine privileges |
| JS engine output -> Dart | Engine-produced strings are decoded into typed Dart data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Tampering (code injection) | JsEngineService.call argument marshalling | mitigate | Arguments only via jsonEncode plus U+2028/2029 escaping. The method name goes into the source only after the regex allow-list, and the namespace must be in the fixed `namespaces` set (property access via jsonEncode(name) bracket). The smoke check (6) proves that a hostile string round-trips as data |
| T-02-09 | Tampering | bundle asset load | mitigate | isError is checked on the bundle evaluate, then an explicit verification of the 8 namespaces + __openGymLibMeta. On failure the runtime is disposed and the recovery screen is shown (no half-loaded engine) |
| T-02-10 | Spoofing / Tampering | JavaScriptCore 'ERROR:' prefix heuristic | mitigate | Results always travel in a JSON envelope {ok}/{e}. Dart requires a decodable envelope, so a string result can never be mistaken for, or hide, an error |
| T-02-05 | Elevation of privilege | flutter_js fetch shim | mitigate | getJavascriptRuntime(xhr: false): the bundled code gets no network capability |
| T-02-11 | Tampering | result decoding | mitigate | Strict js_codec helpers throw JsBridgeException on any type mismatch. No `as` casts on dynamic, rawResult is never used (strict-casts + avoid_dynamic_calls lints) |
| T-02-12 | Denial of service | ~1 MB synchronous bundle evaluate at startup | accept | One-time cost measured (LOAD_MS recorded). It runs before runApp behind the native splash; revisit only if the measured time is user-visible |
</threat_model>
