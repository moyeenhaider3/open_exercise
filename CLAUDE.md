## Project

**open_exercise — openGym for Flutter**

A native Flutter (Android/iOS) port of **openGym** (`../openGym/`), the self-hosted gym and body-weight tracker. The goal is a 1:1 replica of openGym's features, offline persistence and UI layout, built with native Flutter widgets (Material 3) instead of a React/Capacitor WebView.

**Core Value:** Log a workout fully offline with **exactly** the same numbers as openGym. The same inputs must give identical 1RM estimates, progression suggestions, plate math and volume/fatigue results, because the original JavaScript logic runs unchanged.

### Constraints

- **License:** AGPL-3.0-or-later. This port is a derivative work and must use the same license.
- **Stack (user-mandated):** flutter_bloc, equatable, sqflite, Dio (OpenAPI-generated), flutter_js, flutter_local_notifications, flutter_passkey_service, xml, path_drawing.
- **Process:** one phase at a time. Wait for user approval before starting each next phase.
- **No tests (user-mandated, enforced):** never write, generate, or plan test code: no `test/`, `integration_test/` or `test_driver/` files, no `*_test.dart`, and no test dev-dependencies (`bloc_test`, `mocktail`, `sqflite_common_ffi`, etc.). Plans must not contain test tasks, TDD tasks, or test-based acceptance criteria. Use `flutter analyze` and source/CLI assertions for verification instead. A PreToolUse hook in `.claude/settings.json` blocks writes to test paths.

## Technology Stack

- Flutter/Dart SDK ^3.13.2, Material 3.
- State: `flutter_bloc` + `equatable`. Persistence: `sqflite`.
- Network: `dio` + a `retrofit` client generated by `openapi_retrofit_generator` from
  `third_party/opengym/openapi.yaml` into `lib/core/api/generated` (committed; never hand-edit,
  regenerate via `tool/gen_api.sh`). Routing: `go_router`.
- Domain logic: `flutter_js` (QuickJS on Android, JavaScriptCore on iOS) running
  `assets/js/opengym-lib.bundle.js`, built by `tool/gen_js_bundle.sh` with pinned esbuild 0.28.2.
- Mandated but not yet added (later phases): `flutter_local_notifications`, `flutter_passkey_service`,
  `xml`, `path_drawing`.

## Conventions

- SPDX `AGPL-3.0-or-later` header on every hand-written source file and shell script.
- Bloc: feature folder layout `bloc/ data/ view/`; `sealed class` Equatable states/events with
  `final class` subclasses and `props`; a single `on<Event>(_onEvent, transformer: _sequential())`;
  repository injected via constructor.
- Prefer `final class` with const constructors; models expose `fromJson`/`toJson`.
- No domain math in Dart (JS-04): call the typed facades exported from `lib/core/js/opengym_js.dart`.
- No tests of any kind (project rule, hook-enforced). Verify with `flutter analyze`,
  `bash tool/js04_audit.sh`, and `bash tool/run_parity.sh <device-id>`.

## Architecture

- `lib/app`: composition root (`AppDependencies`, `MultiRepositoryProvider` in `app.dart`).
- `lib/core/api`: generated OpenAPI/retrofit client (`generated/`) + hand-written `ApiClientFactory`.
- `lib/core/data`, `lib/core/db`: `GymStateRepository` over `AppDatabase` (sqflite).
- `lib/core/js`: `JsEngineService` + typed facades/models, barrel `opengym_js.dart`.
- `lib/core/models`, `lib/core/router`, `lib/core/theme`: domain models, go_router, theming.
- `lib/features/shell`: first feature (`bloc/ data/ view/`).
- `tool/`: codegen scripts, JS bundling/fixture tooling (`tool/js/`), parity harness (`tool/parity/`).
- `third_party/opengym`: vendored openGym JS source + OpenAPI spec. `assets/js`: the built JS bundle.
- Data flow: widget -> Bloc -> `GymStateRepository` (sqflite) / `JsEngineService` facades;
  `AppDependencies` is wired in `lib/app/app.dart` via `MultiRepositoryProvider`.
